PROFILI — PIPELINE (AFTER INNGEST JOBS)
=======================================
Monolith: Next.js. Jobs: Inngest. Voice context is still published profile_json.


A. OWNER PARSE (ASYNC)
----------------------
1. Client uploads PDF to Storage resumes/{userId}/{uuid}.pdf
2. POST /api/resume/parse verifies owner + path, upserts profiles
   parse_status=parsing, parse_error=null (does not unpublish during the job)
   emits resume.uploaded, returns 202
3. Inngest parse-resume (retries, Gemini concurrency 2):
   download PDF -> unpdf -> Gemini JSON (3.8 -> 3.7 -> 3.1-flash-lite + zod)
   -> write profile_json + greeting, parse_status=ready
   If the profile was published, status becomes draft so they re-publish.
   Exhausted retries -> parse_status=failed + short parse_error
4. UI: Realtime on profiles + 2s poll. Stages Uploading / Reading / Understanding.
   Failed: error + Retry (re-emits the same resume_path)


B. VISITOR CALL (SYNC EXCEPT END JOB)
-------------------------------------
5. GET /p/{slug} reads published profile
6. POST /api/voice/token: atomic hourly buckets, insert calls,
   AssemblyAI token max_session 35s (falls back to 60s if API rejects)
7. Browser WS session.update uses profile_json as context (no Gemini)
8. session.ready -> POST /api/voice/session saves assembly_session_id
9. Live STT still POSTs /api/voice/transcript (UX only)
10. Normal hangup: awaited POST /api/voice/end
    Tab close: sendBeacon /end (pagehide/beforeunload)
    /end is idempotent: set ended_at, insight_status=pending, emit call.ended once
11. Cron twice a day (00:00 and 12:00 UTC): calls with no ended_at and started_at older than 90s
    get ended_at = started_at+30s and the same call.ended event


C. AFTER CALL (ASYNC, ASSEMBLYAI CANONICAL)
-------------------------------------------
12. Inngest finalize-call, skip if insight_status=ready:
    wait for assembly_session_id
    GET session, download timeline (re-fetch URLs, never store them)
    upsert transcript_turns on (call_id, seq)
    if no turns: skipped; else Gemini insights -> ready
    onFailure: failed
13. Dashboard GET /api/voice/calls is read-only.
    pending/processing -> Processing…
    failed/skipped -> Retry insights (re-emits call.ended)


D. LOCAL RUN
------------
  pnpm dev
  pnpm inngest:dev   (points at http://localhost:3000/api/inngest)
Production: Inngest Cloud + INNGEST_EVENT_KEY + INNGEST_SIGNING_KEY
  and SUPABASE_SERVICE_ROLE_KEY (parse job downloads the PDF).
