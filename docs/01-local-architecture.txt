PROFILI — LOCAL INFRASTRUCTURE
================================
Audience: run the full product on one machine (or one VPS) at production quality.
Goal: same event contracts as cloud, so you can later swap hosts without rewriting the app.

This is NOT a toy stack. It is the production architecture, compressed onto Docker Compose.
OpenAI Realtime still talks to OpenAI over the network. Everything else stays local.


1. WHAT THE PRODUCT DOES
------------------------
User signs up / logs in
  -> uploads a resume PDF
  -> we parse it and extract a structured profile
  -> we build a voice agent
  -> recruiters talk to that agent (OpenAI Realtime stream)
  -> we store the conversation transcript
  -> we generate analysis for the owner (what people asked, coverage, follow-ups)

Current app state (today):
  - Next.js 16 App Router, client-only demo session in localStorage (profili-demo-user)
  - Resume upload and agent create are mocked
  - Public talk page is /talk/[handle]
  - Insights UI exists, data is mocked

This file is the local backend that replaces those mocks.


2. LOCAL STACK (DOCKER COMPOSE)
-------------------------------
  [browser]

      | HTTPS (localhost)
      v

      |
      |-----+------------------+--------------------+
      |     |                  |                    |

Run with:
  docker compose up
  pnpm dev          (or also containerize Next)

One compose file. One network. Persistent volumes for postgres, redis, minio.


3. WHY THIS SHAPE (NOT "JUST NEXT.JS")
--------------------------------------
Resume parse, agent build, and analysis are slow and bursty.
Voice calls are live and latency-sensitive.

Never put those on the same request thread as "upload PDF" or "start call".

  SYNC path (must be fast, < 200ms):
    login, session, presign upload, agent status poll, mint realtime token, read insights

  ASYNC path (event-driven, retryable):
    parse resume, extract facts, embed chunks, compile agent config, analyze call

  REALTIME path (separate, do not block on workers):
    browser <-> OpenAI Realtime
    we only mint a short-lived session token and persist transcript events


4. EVENT-DRIVEN CORE
--------------------
Postgres is the source of truth.
Redis Streams is the bus.
Workers are dumb, idempotent, and horizontally copy-pasteable (run N of each).

Outbox pattern (do not publish events from the API and hope):
  1. API writes domain row + outbox row in ONE postgres transaction
  2. A small outbox-publisher process reads unpublished outbox rows and XADD to Redis Streams
  3. Workers consume with consumer groups (parse, agent, analysis)
  4. Worker writes result + next outbox event in one transaction
  5. ACK the Redis message only after the DB write succeeds

If Redis dies, events wait in outbox.
If a worker dies mid-job, the message is reclaimed (XAUTOCLAIM).
If the same event is delivered twice, idempotency_key makes the second a no-op.

Streams (names):
  profili.jobs.parse
  profili.jobs.agent
  profili.jobs.analyze
  profili.jobs.dead                       (poison messages after N retries)

Domain events (stored in outbox, also useful for audit):
  user.created
  resume.uploaded
  resume.parse.requested
  resume.parsed
  resume.parse.failed
  agent.build.requested
  agent.ready
  agent.build.failed
  call.started
  call.ended
  analysis.requested
  analysis.ready
  analysis.failed

State machines (never skip states):

  Resume:   uploaded -> parsing -> parsed | failed
  Agent:    pending  -> building -> ready | failed
  Call:     ringing  -> live -> ended | aborted
  Analysis: pending  -> running -> ready | failed

The UI polls GET /api/agents/:id (or uses SSE) until agent.status = ready.
Do not hold an HTTP request open for the whole parse.


5. FILE STORAGE (MINIO)
-----------------------
S3 API locally. Same SDK (AWS S3 client) as production.

Buckets:
  profili-resumes          private
  profili-recordings       private, optional, only if you proxy audio
  profili-exports          private, generated PDF/CSV of analysis

Object keys:
  resumes/{user_id}/{resume_id}/original.pdf
  resumes/{user_id}/{resume_id}/text.txt
  recordings/{user_id}/{call_id}/session.ndjson     (realtime events, not raw wav by default)

Upload path (this is how you survive concurrent uploads even on a laptop):

  1. Client POST /api/resumes  { filename, contentType, bytes }
  2. API checks auth, quota, mime, size cap (10 MB), virus-scan hook later
  3. API inserts resumes row status=uploaded, outbox resume.uploaded
  4. API returns { resumeId, uploadUrl, headers }   (presigned PUT, 5 min TTL)
  5. Browser PUTs the PDF straight to MinIO. Next.js never buffers the file.
  6. Client POST /api/resumes/:id/complete
  7. API verifies object exists + etag/size, writes resume.parse.requested
  8. parse-worker picks it up

Never stream the PDF through the Next.js server. That is how concurrent uploads melt a single Node process.


6. PARSE WORKER
---------------
Job: resume.parse.requested
Idempotency: resume_id

Steps:
  1. GET PDF from MinIO
  2. Extract text (pdf-parse / Docling / pdftotext). Keep page offsets.
  3. If text is thin, OCR page images (optional local Tesseract). Skip OCR if text is good.
  4. LLM extract into ResumeDocument JSON (schema below). Use OpenAI JSON mode, or Ollama locally.
  5. Chunk text ~500 tokens with 80 token overlap. Embed. Write resume_chunks (pgvector).
  6. Write parsed_resumes row. Set resumes.status = parsed.
  7. Outbox: resume.parsed + agent.build.requested

Keep raw text. Re-extract is cheaper than re-uploading.

ResumeDocument (JSON, versioned):
  schema_version
  full_name, email, phone, links[]
  headline, summary
  skills[]                         { name, kind: language|framework|cloud|tool, years? }
  experience[]                     { company, title, start, end, bullets[], tech[] }
  projects[]                       { name, role, bullets[], tech[] }
  education[]
  certifications[]
  languages[]
  gaps_or_notes[]                  (model uncertainty, not shown to recruiters)


7. AGENT WORKER ("MAKE THE AGENT READY")
----------------------------------------
Job: agent.build.requested
Idempotency: agent_id + resume_content_hash

This is more than "paste resume into a prompt".

Build artifacts stored on agents + agent_versions:

  a) Persona
     name, role, greeting, voice_id, language, personality, formality, verbosity
     (maps to the current Profile type in lib/types.ts)

  b) Instructions (system prompt)
     compiled from ResumeDocument + owner settings
     rules: answer as the candidate, never invent employers, say "I don't have that" on gaps
     include a short "facts card" (title, years, top 8 skills, last 3 jobs)

  c) Retrieval index
     resume_chunks already in pgvector
     tools the realtime model can call:
       search_resume(query) -> top k chunks
       get_experience(company_or_index)
       get_skills()

  d) Realtime session template (JSON)
     model, voice, turn_detection, input_audio_transcription, instructions, tools[]
     this is what POST /api/talk/:handle/session copies from

  e) Public handle
     unique, from name slug, same as /talk/[handle]

When this job commits, agents.status = ready.
The talk page may go live.

OpenAI Stream / Realtime:
  You do not keep a warm OpenAI socket per user 24/7. That does not scale and costs money.
  You store the TEMPLATE. You mint an ephemeral session when a recruiter hits Start.

Local extra:
  You can run embeddings locally (nomic-embed-text via Ollama) to save money.
  Voice must still be OpenAI Realtime unless you later swap to a local STT/TTS stack (Whisper.cpp + a TTS). That is a different product.


8. VOICE CALL PATH (LOCAL)
--------------------------
  Recruiter browser
      |  GET /talk/waseem           (Next page)
      |  POST /api/talk/waseem/session
      |     checks agent.ready, rate limit, creates calls row status=live
      |     asks OpenAI for ephemeral realtime client secret
      v
  Browser opens WebRTC/WebSocket to OpenAI Realtime (not through Next)
      |
      |  client sends audio
      |  OpenAI returns audio + item transcripts
      |
      +--> browser POSTs transcript deltas to /api/calls/:id/events
           (small JSON, batched every 1-2s, or a dedicated WS to Next)
      |
      hangup
      POST /api/calls/:id/end
      outbox: call.ended + analysis.requested

Why not proxy all audio through your server locally:
  - You would need a second realtime media process
  - You add latency
  - You still need OpenAI on the other side

When you NEED server-side audio (recording, compliance, barge-in logs):
  add a thin "voice-gateway" Node/Go process that sits between browser and OpenAI,
  tees events to Redis, writes recordings to MinIO. Optional. Not needed for v1.

Transcript source of truth:
  Prefer the realtime transcription events OpenAI already emits.
  Do not wait to re-run Whisper on a wav unless the live transcript is garbage.


9. ANALYSIS WORKER
------------------
Job: analysis.requested
Idempotency: call_id

Input: calls row + transcript_turns ordered by t
Prompt: structured JSON, not a blog post.

Output (analyses.report jsonb):
  duration_s
  recruiter_intent              (screen / deep-dive / culture / stale)
  topics[]                      { name, seconds, turn_ids[] }
  questions[]                   { text, answered: yes|partial|no, resume_refs[] }
  skills_mentioned[]            vs skills on the resume (covered / missed / claimed-off-resume)
  sentiment_arc                 start -> end
  risk_flags[]                  hallucination, contradiction, "I don't know" on a core job
  suggested_follow_ups[]        for the candidate to tighten the agent next
  summary_for_owner             5-8 lines

Then the Insights page reads:
  recent calls, top questions this week, coverage heat, visitor list (separate table)


10. DATABASE SCHEMA (POSTGRES)
------------------------------
Extensions: pgcrypto, vector (pgvector)

users
  id              uuid pk
  email           citext unique not null
  name            text not null
  handle          citext unique not null          -- public /talk/{handle}
  password_hash   text                            -- local: email+password; later add oauth
  created_at      timestamptz default now()
  deleted_at      timestamptz

sessions
  id              uuid pk
  user_id         uuid fk users on delete cascade
  token_hash      text unique
  expires_at      timestamptz not null
  created_at      timestamptz default now()

resumes
  id              uuid pk
  user_id         uuid fk users
  object_key      text not null                   -- minio key
  file_name       text not null
  content_type    text not null
  bytes           int not null
  sha256          text
  status          text not null                   -- uploaded|parsing|parsed|failed
  error           text
  created_at      timestamptz default now()

parsed_resumes
  id              uuid pk
  resume_id       uuid unique fk resumes
  schema_version  int not null
  document        jsonb not null                  -- ResumeDocument
  raw_text        text not null
  model           text not null
  created_at      timestamptz default now()

resume_chunks
  id              uuid pk
  resume_id       uuid fk resumes
  chunk_index     int not null
  page            int
  content         text not null
  embedding       vector(1536)                    -- or 768 if local embed model
  unique (resume_id, chunk_index)

agents
  id              uuid pk
  user_id         uuid unique fk users            -- one live agent per user in v1
  resume_id       uuid fk resumes
  handle          citext unique not null
  status          text not null                   -- pending|building|ready|failed
  voice_id        text not null
  language        text not null default 'en'
  personality     text not null
  formality       real not null
  verbosity       real not null
  greeting        text not null
  current_version int not null default 1
  created_at      timestamptz
  updated_at      timestamptz

agent_versions
  id              uuid pk
  agent_id        uuid fk agents
  version         int not null
  instructions    text not null
  realtime_config jsonb not null                  -- OpenAI session template
  facts_card      jsonb not null
  created_at      timestamptz
  unique (agent_id, version)

calls
  id              uuid pk
  agent_id        uuid fk agents
  user_id         uuid fk users                   -- owner, for RLS
  visitor_id      uuid fk visitors null
  status          text not null                   -- live|ended|aborted
  started_at      timestamptz not null
  ended_at        timestamptz
  duration_s      int
  openai_session  text                            -- their session id, not a secret
  ip_hash         text
  user_agent      text

visitors
  id              uuid pk
  agent_id        uuid fk agents
  display_name    text                            -- optional, from them or inferred
  email           text
  company         text
  first_seen_at   timestamptz
  last_seen_at    timestamptz

transcript_turns
  id              uuid pk
  call_id         uuid fk calls on delete cascade
  seq             int not null
  speaker         text not null                   -- visitor|agent
  text            text not null
  started_at      timestamptz
  ended_at        timestamptz
  source          text not null                   -- realtime|whisper_repair
  unique (call_id, seq)

analyses
  id              uuid pk
  call_id         uuid unique fk calls
  status          text not null
  report          jsonb
  model           text
  error           text
  created_at      timestamptz

outbox
  id              bigserial pk
  topic           text not null
  payload         jsonb not null
  idempotency_key text unique not null
  published_at    timestamptz
  created_at      timestamptz default now()

processed_jobs
  idempotency_key text pk
  worker          text not null
  processed_at    timestamptz default now()

Indexes:
  resumes (user_id, created_at desc)
  calls (agent_id, started_at desc)
  transcript_turns (call_id, seq)
  resume_chunks using ivfflat (embedding vector_cosine_ops)
  outbox (created_at) where published_at is null

14. CONCURRENCY EVEN ON A LAPTOP
--------------------------------
Uploads: presigned PUT, Next.js only writes metadata. 50 parallel uploads is fine.
Parse:   limit LLM concurrency per worker (p-limit 4). Extra jobs wait in Redis.
Agent:   one build per user at a time (unique index / advisory lock on user_id).
Talk:    OpenAI bears media. Your API only mints tokens + accepts small JSON events.
Analysis:low priority queue so it never starves parse.

Rate limits (Redis):
  upload: 10 / user / hour
  talk session: 30 / agent / hour
  events ingest: 20 rps / call


15. OBSERVABILITY (LOCAL, STILL REAL)
-------------------------------------
  - request id on every API log
  - job id + resume_id / call_id on every worker log
  - outbox lag gauge (count unpublished)
  - stream lag (XINFO GROUPS)
  - MinIO disk usage
  - agent ready time histogram (uploaded_at -> agents.ready)

You can run Prometheus + Grafana later. For now, structured JSON logs to stdout are enough.


16. FAILURES YOU MUST HANDLE
----------------------------
  PDF is a scan          -> OCR path or fail with a clear status
  LLM JSON invalid       -> retry with repair prompt, then failed
  duplicate complete()   -> idempotent, same resume_id
  OpenAI realtime down   -> talk page shows "voice unavailable", do not mark agent failed
  worker crash mid-embed -> retry whole job, unique (resume_id, chunk_index) prevents dupes
  user uploads v2 resume -> new resume row, new agent_version, old calls stay on old version


17. WHAT NOT TO DO LOCALLY
--------------------------
  - Do not parse the PDF inside the upload route
  - Do not store the PDF in postgres
  - Do not keep a long-lived OpenAI socket per agent
  - Do not use localStorage as the user database past this demo
  - Do not re-transcribe the full call before showing the owner anything; persist live turns first
